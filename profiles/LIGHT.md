# AI-Assisted Development Project Operating Model 2.0
## Profile: LIGHT


1. **Purpose.** LIGHT governs low-risk persistent work that benefits from recoverability and authority discipline but does not justify a heavier profile.
2. **Authority.** Keep one declared source of truth for persistent state. Avoid duplicate current-state documents.
3. **Minimum state.** Persist only enough to recover objective, trusted current baseline or source, blockers and next action.
4. **Discover first.** Recover available state before asking the user to repeat it.
5. **Proportional evidence.** Preserve evidence only for decisions or outcomes whose future interpretation materially depends on it.
6. **External sources.** Reference external authority directly rather than copying it into a second source of truth.
7. **Safety.** LIGHT does not weaken CORE fail-closed authorization, target identity, destructive-operation or historical-integrity rules.
8. **No implicit release lifecycle.** Candidate/release machinery is not required unless the work is reclassified to DEV.
9. **Escalation.** Reclassify prospectively when risk, connected mutation, reproducibility, release, formal approval or reuse requirements outgrow LIGHT.
10. **Closure.** Preserve the accepted/current result and any material limitation; do not create transition packages merely because a session ends.
